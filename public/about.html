무엇을 푸는 도구인가

팀장·대표가 "누가 무엇을 했고, 지금 무엇을 하고 있고, 어디가 막혀 있는지"를 사람에게 묻지 않고 알게 하는 자동 스탠드업 대시보드다. 스탠드업 미팅, "그거 어떻게 됐어?" 하는 질문, 진행 상황 보고서를 자동화된 화면 하나로 대체하는 것이 목표다.

설계 원칙 — 출퇴근이 아니라 작업 이벤트를 그린다.
자리에 있는지(presence)는 감시일 뿐 정보가 아니다. 이 화면의 모든 시각 요소는 실제 깃 이벤트에 1:1로 대응하며, 데이터에 없는 것은 그리지 않는다. 재미(픽셀 오피스)와 정확성(깃 히스토리)이 충돌하지 않는 이유다.

전체 구조

모든 작업은 결국 깃 푸시·PR로 나타난다는 사실을 이용해, 에이전트든 사람이든 어디서 작업하든(로컬 CLI·웹 원격 세션) 리포 하나만 계측하면 전체가 보인다.

수집: git 필수, API 보강

  • git 트랜스포트 — 로컬 클론에서 git fetch 후 브랜치·커밋·작성자를 읽는다. GitHub API가 막힌 네트워크에서도 동작하는 기본 경로. 멤버 목록은 설정 없이 커밋 작성자에서 자동 발견된다.
  • REST API 보강 — 접근 가능하면 열린 PR·CI 체크·머지 이력을 더한다. 첫 호출에서 401/403이면 스스로 비활성화되고 git 수집만으로 동작한다.
  • authorAliases — 에이전트 커밋(noreply@anthropic.com 등)을 계정 주인 이름으로 귀속시킨다. 팀원 추가 시 이메일→이름 매핑만 늘리면 된다.

Q&A 엔진 사다리

질문("오늘 뭐 됐어?", "막힌 거 있어?")은 현재 스냅샷을 근거로 답한다. 환경에 따라 가능한 가장 좋은 엔진이 자동 선택되고, 실패하면 아래로 폴백한다.

  1. 서버 모드: Anthropic API 키 → claude CLI(Pro/Max 구독, 키 불필요) → 규칙 기반
  2. 정적/브라우저 모드: 크롬 내장 AI(Gemini Nano, 다운로드 없음) → WebLLM(Qwen3.5 0.8B~9B를 기기 GPU에서 실행, 기기 메모리 맞춤 자동 선택) → 규칙 기반

어느 경로든 API 비용·구독 없이도 동작한다는 것이 핵심 — 규칙 기반은 LLM 없이 데이터 조회로 답한다.

Evidence 루프: 증거가 첨부되는 개발

에이전트(또는 사람)가 개발할 때의 순환이다:

  1. 구현 후 npm run verify — 하네스가 서버를 띄우고 Playwright로 실제 화면을 연다
  2. 렌더링·Q&A 왕복을 검사하고 스크린샷을 찍는다 (데모·라이브·모바일 정적 3종)
  3. 스크린샷 + 체크 결과가 .guild/evidence/<브랜치>/에 저장되고 커밋된다
  4. 대시보드 Evidence 갤러리와 리뷰어가 같은 이미지를 본다 — "된다"는 말 대신 화면으로 증명

보안 설계 요약

  • 서버는 기본 127.0.0.1 바인딩 — 개방은 HOST 명시 + 토큰 인증 권장
  • LLM 호출 동시 2건 제한 — 구독·크레딧 소진 공격 방지
  • 커밋 메시지·질문은 신뢰할 수 없는 입력으로 취급 — CLI 모드는 도구 완전 비활성(--tools ""), 프롬프트에 데이터/지시 경계 명시
  • 잔여 위험 고지: 조작된 커밋 메시지가 요약 "문구"를 왜곡할 가능성은 LLM 특성상 0이 될 수 없다. 현황판은 참고용, 원본은 항상 깃 히스토리다
